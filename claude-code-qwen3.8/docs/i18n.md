# Internationalization (i18n catalog)

i18n lives in `app/adapters/i18n/` (step 18, ADR 0004). Every user-facing display
string lives in `strings.ts`, translated into **en / ja / es**, with **English as the
fallback**. No presentation adapter hard-codes a display string — the HUD, overlays,
settings panel, sound control, and d-pad all read through `t(key)`.

## Locales

- `SUPPORTED_LOCALES = ['en', 'ja', 'es']` — the order here drives the language
  picker's listing.
- `DEFAULT_LOCALE = 'en'` — the default and the fallback for any key absent from the
  current locale.
- `setLocale(loc)` switches the locale and notifies subscribers; `getLocale()` reads it.
- `t(key)` returns the current locale's string for `key`, falling back to English.

## Compile-time completeness

The `EN` object is the **single source of truth for the set of keys**: `StringKey` is
`keyof typeof EN`, and the JA / ES catalogs are typed as
`Record<StringKey, string>`. So a missing or misspelled key in any locale is a
**compile-time error, not a runtime blank**. `t()` only accepts a `StringKey`, so a
free-form string at a call site is also a type error (the settings panel casts its
dynamically-built `'lang.' + loc` keys).

## The key set

Grouped by the UI surface that reads them:

| Group | Keys |
|---|---|
| Brand / title | `title.name` (NEON SNAKE — kept identical across locales), `title.start`, `title.move`, `title.hints` |
| HUD | `hud.score`, `hud.best`, `hud.level`, `hud.max` |
| Pause | `pause.title`, `pause.resume` |
| Game over | `gameover.title`, `gameover.score`, `gameover.best`, `gameover.restart` |
| Level-up banner | `levelup.banner` (`Level {n}` — `{n}` is a placeholder) |
| Sound control | `sound.toggle` |
| D-pad | `dpad.up`, `dpad.down`, `dpad.left`, `dpad.right` |
| Settings | `settings.title`, `settings.effects`, `settings.sound`, `settings.dpad`, `settings.fps`, `settings.language`, `settings.close` |
| Common | `common.on`, `common.off` |
| Language names | `lang.en`, `lang.ja`, `lang.es` |

## Live re-render on a locale change

`subscribe(fn)` registers a callback fired on every locale change. The presentation
adapters subscribe and **re-read their labels through `t()`**, so switching the language
in the settings panel immediately repaints the HUD, overlays, settings labels, the
sound control's accessible label, and the language-picker options — no reload. The
accessible `aria-label`s are re-read too, so the localized names stay correct for screen
readers.

## Notes

- **`{n}` placeholders** are substituted by the presentation (the level-up banner), not
  baked into the catalogs.
- The **brand name** `NEON SNAKE` is intentionally identical in all three locales (it is
  a name, not a sentence).
- Unit tests (`tests/unit/i18n.test.ts`) pin that every locale carries every key, that
  `t()` falls back to English for a missing key, and that a locale change fires the
  subscribers.
